## Durable indexed-agent checkpoints

- Done: inventory, author and source-review calls now rebuild each model continuation from the
  unchanged prompt plus one bounded `topic-agent-checkpoint/1`. Previous assistant/tool messages do
  not return to the wire. The checkpoint retains compact source-access facts and the most recent
  exact source sentences; the final answer must reread and retain every sentence covered by its
  typed source spans.
- Persistence and recovery: every checkpoint is a run/stage/role/index-bound immutable `checks`
  artifact published before dispatch. Sequence zero depends on the prepared inputs; every later
  sequence also depends on its direct parent; every model response depends on the checkpoint it saw.
  After a known provider failure, the workflow loads and verifies the latest checkpoint and retries
  the same request on the current or next qualified route. Unknown outcomes keep the existing fence.
- Admission: new answers produce `topic-source-inspection/2`, which binds the final checkpoint hash,
  request sequence, complete source-tool trace, retained exact sentence IDs and eviction count. An
  earlier read that has left working context is progress evidence but cannot ground a final claim.
  Historical v1 inspection remains readable under its original rules.
- Limits: 256 successful calls, 8,192 returned IDs, 320 retained sentences, 128 KiB retained exact
  text and a 384 KiB checkpoint. A third identical successful call is refused. These are payload
  safety envelopes, not production-tuned duration or output-count limits; bounded portfolio
  reconciliation is still required when final evidence cannot coexist within them.
- Qualification: indexed route pre-flight uses the same history processor. Its tool/final fixture
  confirms that the second request has only the original prompt and checkpoint, while both physical
  requests remain separately accounted.
- What needed care: PydanticAI resolves a history processor's type annotation at runtime, so the

  persisted checkpoints; it did not restore them after a known provider failure. The completed path

### LinkedIn draft

An indexed transcript only solves the first half of the long-context problem. If an agent keeps its
entire tool conversation, the prompt grows again; if a provider fails, a restarted agent can repeat
source discovery and pay twice.

Temnia's inventory, author and source-review loops now rebuild every continuation from the original
instructions and one bounded checkpoint. The checkpoint records the source regions visited and
retains only recent exact sentences. It is stored before dispatch in an immutable parent chain, and
the final answer is accepted only when all speech it cites is still present in the exact checkpoint
attached to that response. A known provider failure reloads the same state for retry or route
fallback; an unknown outcome remains fenced.

This is local recovery and payload evidence, not a claim that two- or four-hour editorial quality is
solved. Candidate/media inspection, portfolio decomposition and real long-source evaluation remain.
