## How

The one mechanism worth explaining: the scope never comes from the request. `resolveScope()` is one
function in the web app; today it returns the seeded organization and user from the contracts package,
and at S24 Better Auth replaces its body. The hello workflow exists to prove the organization id
crosses the language seam intact: the Python activity copies it from the input and the Zod output
schema refuses anything else. The isolation suite is the other half of the same idea, built before the
first table so a table without forced RLS cannot be merged.

## Went wrong

- **pnpm 10 cannot self-switch to pnpm 12.** The `packageManager` field made the installed pnpm 10
  download 12.3.4's npm tarball and fail with `ENOEXEC`, because 12 is a native binary behind a shell
  launcher. The official installer put 12 under `~/Library/pnpm/bin`; the shell sessions opened before
  that still resolve the old binary, which is how the shadcn CLI failed three times before I noticed.
- **pnpm 12 renamed the build allow-list.** `onlyBuiltDependencies` is gone; the key is `allowBuilds`
  and a failed install writes a placeholder block into `pnpm-workspace.yaml`, which I then duplicated.
- **The 24-hour release-age gate bit on day one.** Playwright 1.63.0 was published at 22:44 UTC on
  2026-09-04, inside the window. Pinned 1.62.1 as the tech stack said. Vitest 5.0.0 (2026-09-03)
  passed the gate and was adopted; it is a sprint boundary.
- **Moving a uv project breaks its virtualenv.** Every script in `.venv/bin` embeds the interpreter's
  absolute path in its shebang; after the move, `pyright` and `pytest` failed with "No such file" while
  `ruff`, a native binary, kept working. Deleted the venv and synced again. I also ran two `uv`
  commands on the same project concurrently once, which is a race; the rule is now written down.
- **Temporal needs the contract types at runtime.** ruff's TC001 asked me to move the pydantic model
  imports into a `TYPE_CHECKING` block; the SDK resolves the run method's type hints to deserialise
  payloads, so the workflow test failed with `NameError`. The imports stay real, with a comment.
- **pydantic refuses a regex on a UUID.** Zod emits both `format: uuid` and a `pattern` for
  `z.uuid()`; datamodel-codegen typed the field `UUID` and attached the pattern, which pydantic rejects
  at import time. The emitter now strips `pattern` wherever `format` is `uuid`.
- **Ultracite's first fix pass reformatted the design prototypes under `docs/`.** 589 findings, almost
  all in `temnia-studio.html`. Reverted from git and excluded `docs`, the vendored `components/ui`,
  and both generated folders from Biome.
- **The web image's pnpm download failed inside Docker.** GitHub's release CDN refused the connection
  from the build VM; the pipeline image, which installs uv from a GHCR image, built fine at 304 MB.
  Fixed by installing pnpm from the npm registry inside the image (its package carries the musl
  binary as an optional dependency): 4.9 s, and no GitHub URL in the build.
- **`docker compose up --wait` exits 1 once a one-shot job has finished.** The schema and namespace
  jobs exit 0 by design; compose counts them as failed anyway, which the gate surfaced on its second
  run. The wait set now names the four long-running services (`pnpm services`).
- **`turbo prune --docker` leaves root config files behind.** The pruned context had every workspace
  package but not `tsconfig.base.json`, so Turbopack failed to resolve `extends` and the web image
  build died on the gate's third run. One explicit `COPY` in the installer stage.
- **The verified-PR script asked GitHub for a workflow that did not exist yet.** `gh run list
  --workflow ci.yml` resolves the file on the default branch, and this PR is the one that adds it, so
  the wait after opening PR #3 failed while the check itself had already passed in 6 s. The lookup now
  goes by commit and workflow name.
- **Temporal's images have no bash.** The schema job died at `exec: /bin/bash`. Rewritten for `sh`,
  health check on `nc -z`.
- **The shell kept the working directory of the previous command.** Three separate mistakes came
  from it: root files written into `apps/web`, the pipeline scaffolded at `apps/web/apps/pipeline`,
  and shadcn run from the wrong directory. Every command now starts with an absolute `cd`.
