## Fix PR: judge a physical-only repair by its effect

The refused repair was correct. The prompt allows `replace_extent` for an extension; the
validator accepted only the `extend_start`/`extend_end` labels for a physical-only finding,
so a one-sentence opening extension with the other label failed, and the atomic rule threw
away the other five operations. The rule now names the edge from the effect (exactly one
edge, moved outward) and keeps every other physical-only check. Also: the stop reason now
carries the refusal diagnostic; a 402 says credits or key limit, not "change the route";
a conclusive HTTP rejection settles at a known zero so the reservation is released; the
panel lists withheld candidates with their findings and shows the transcript notice only
once a run has recorded its revision. The atomic-repair rule itself is unchanged; whether
partial acceptance should replace it is the next decision, measured on the re-run.
