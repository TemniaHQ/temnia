## What went wrong

Export first failed because the Python contract generator applied an RFC3339 string pattern to a
parsed datetime. Fixing the generator allowed the browser to reach export and later recovery
controls. Starting a second chapter run on the same source then exposed an artifact identity
conflict. Evidence publication carried a consumer run ID despite having a source-scoped identity.
Removing that transient metadata, while preserving strict bytes and dependency checks, fixed the
second run. Both runs share one accepted evidence artifact and one storage ledger entry.

The first live GPU qualification then exposed a separate integration defect: recognition and
alignment succeeded in their own containers, but diarization referenced a WhisperX submodule that
the isolated process had not imported. All three attempts reached known terminal states; the two
accepted checkpoints and independent coverage artifact were preserved and hash-verified. The
import correction follows the pinned release's own explicit submodule import. This failed run
remains part of the accounting; the replacement short and long tests use tighter limits to remain
within the original aggregate exposure ceiling.

A final rollout audit also removed the worker's local fallback for an omitted deployed speech build
ID and its disconnected progress-Dict override. Boot now requires the explicit deployment identity;
reader and writer use the protocol's fixed progress channel. Required media-check warnings remain
visible and eligible, while missing checks and failures block acceptance; the docs now state that
rule precisely. Route schema validation is also distinguished from separately retained audition
evidence.

The standalone schema audit found a generator ordering defect: files emitted before their
dependencies were visited contained unresolved references. The aggregate used by Python was
complete. The correction builds all definitions before selecting each contract's reachable set;
the integrity check covers generated documents as well as ordinary contract validation.

The first full gate passed all 635 Python tests but revealed that Turborepo filtered the
database variable from the web task, silently skipping its two PostgreSQL regressions. The
verified push was stopped before publication. The web task now explicitly receives its test
database and local-gate flag, disables database-test caching, and refuses to skip those tests
inside the gate. Final delivery must execute them.

The production browser run then passed the full chapter journey and found three older regressions.
Two were stale test interception contracts: correction commands now carry a revision inside an
object, and their artifact filenames include a mutation UUID and hash. The third was a real
deletion regression: treating every failed workflow as an uncertain external writer also fenced
files rejected during probing. The correction requires bounded, complete evidence that the exact
failed run never scheduled a media writer; the original deletion assertion stays intact.

The next production run passed 17 of 18 browser tests, including deletion and late-save recovery.
The remaining test failed in its own setup: the initial machine revision has no persisted edit
annotations. It now captures the displayed original turn's word indices and independently derives
their documented machine identities before delaying the next revision. The exact revision and
target-word assertions remain intact.

Enabling the web database regressions also exposed a parallel-test isolation race. The database
suite selected an arbitrary project from the seeded organization, which could belong to another
suite and disappear during its cleanup. Its own harness cleanup was also unbounded. The correction
tracks exact fixture identities for isolation assertions and removes only the suite's own graph,
preserving the cross-tenant assertions while allowing database suites to run concurrently.
The update-denial probe also now issues a harmless same-ID SQL update; an empty update followed
by a catch had previously accepted a query-builder error as evidence of database rejection.

## Speech performance follow-up

Rajesh authorized implementing the performance improvements after discussing the slower isolated
GPU run. The work adds an off-thread progress publisher, explicit four/eight-CPU resource profiles,
and a versioned execution graph with independent speaker turns and recognition/alignment. A CPU
join retains both accepted inputs. The original protocol remains readable and replayable.

The controlled experiment uses one frozen model snapshot: 23 regular files totaling 6,624,978,799
bytes. The image separately identifies WhisperX's bundled VAD, tokenizer assets and observed
library versions. The four variants change progress reporting, CPU allocation and scheduling in
steps. The predeclared matrix has four short recovery cases and two reversed long-source blocks,
at most 36 GPU calls and 13,770,018 micros of configured new exposure under a 14,000,000-micro
admission ceiling. This is not an invoice ceiling; prior unresolved exposure remains separate.

Preparation found actual deployment problems before GPU inference. The first CPU preparation
failed because its volume environment was not propagated remotely. The next exposed Modal's
canonical mount root. A successful snapshot initially included two transfer logs; a new snapshot
excludes them. Deploying the speech module by filesystem path also changed its remote import
layout; the package-module entrypoint works and the wrong form is now rejected. All preparation
costs remain unmeasured without authoritative billing evidence.

Independent review found additional cancellation and attribution edges: an exact physical attempt
must match its returned checkpoint, and cancellation after a terminal GPU result must wait for
accounting to commit. The same review covers sibling cancellation, lost handles and one-time
benchmark admission. The first performance commit passed the full gate: 717 Python tests without
skips, 187 web tests, 41 database isolation tests and 18 production-browser tests, with both deploy
images built. The first live short case then completed all three GPU stages but failed to persist
the CPU assignment because the artifact enum omitted its kind. The failure report also referenced
an incorrect dependency column. No later case was admitted. This exposed missing integration-test
coverage despite the green gate: the actual assignment and report SQL need real PostgreSQL tests.

The correction adds the enum through Drizzle and preserves the first run's accepted checkpoints
and 1,062,501 micros of unresolved exposure. Its planned recovery uses a separate CPU-only run
with a one-micro budget, so a cache miss cannot start another GPU attempt. The remaining eleven
cases retain the original journal and ceiling. The corrected assignment and an actual Temporal
recovery passed against migrated PostgreSQL, proving zero new attempts and unchanged original
accounting. The report query and object preservation also passed against real rows from two runs.
The focused benchmark/driver suite passed all 17 tests; Ruff, Pyright and independent review are
clean. Live comparisons and the corrected release gate remain pending; no performance improvement
has been established yet.

The corrected commit's first full gate failed on missing Next.js route globals while `next typegen`
and `next build` ran concurrently. Ordering typechecking after its own build removed that shared-output
race, but the second gate still failed with generated files present. The effective TypeScript
configuration revealed the cause: it included the generated types while excluding their entire
`.next` directory. A stale incremental program retained an unresolved side-effect import after
generation. A nonincremental probe passed; allowing the generated files as explicit roots also
passed with incremental checking. The correction removes the conflicting exclusion and retains
type generation and build ordering. Neither failed gate produced a receipt or admitted more GPU work.
