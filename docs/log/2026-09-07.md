## How

Uppy 6's plugin reads a `s3Multipart` field on the file (the state Golden Retriever persists) and,
when it finds one, forces multipart and resumes through ListParts. That is the whole trick: the
server creates the multipart as before and knows the UploadId from the first second, and the browser
only has to be told. Everything the S1 client was kept for (server-side truth for resume, the grace
window, the reaper's liveness rule) survives unchanged; what changed is who drives the PUTs.

### Went wrong

- **A double-payment bug caught in review, not in production.** Slice A's poll loop only heartbeated
  when a progress note existed, so a slow GPU cold start could run past the five-minute timeout with
  no heartbeat sent, and the retry would then spawn a second GPU job for the same work, the exact
  cost the design exists to prevent. Caught before the gate. Two hardening items went in alongside
  it: failures classified by exception type, and the Modal function refusing the Garage defaults when
  the R2 secret is incomplete.
- **The transcript spec was slow for the wrong reason.** It waited out the real retry ladder to reach
  the failed state instead of asserting against a recording of it. Fixed as noted above.
- **A timezone bug from S1 surfaced under the new hydration watcher.** `toLocaleString` on the Ready
  timestamp rendered differently on the UTC server and a browser set to Kolkata, which only a
  prod-build hydration check would catch. Fixed and tested across three zones.
- **Two PRs open at once.** #19, opened by another session, and #20 from today's work, against the
  one-PR-at-a-time rule. Noted, not resolved.
- **A script name trap for the one-PR rule.** `pnpm pr:verified -- push` maps to the script's `pr`
  mode and would try to open a second PR; pushing to an already-open PR needs
  `node scripts/verified-pr.mjs push` directly. Written down so the next session doesn't rediscover
  it by opening #21.

### Late evening: the substrate redesigned, the harness researched, S3 rewritten

Rajesh read slice C and asked why the substrate had been ported from the TypeScript instead of
designed from the Python ecosystem, which is the reason the pipeline was rebuilt in Python. He was
right; the exit test written from the legacy had stood in for the research. The substrate was
redesigned the same evening: Segment-any-Text sentences through wtpsplit (boundaries predicted
from the text, so the grid no longer depends on Whisper's punctuation), change-point chapter
candidates from sentence embeddings with ruptures, one renderer with ids and timestamps, real
segmentation metrics (Pk, WindowDiff, GHD, window-tolerant F1 with density, purity, and coverage,
tIoU-F1), and the legacy rules kept as a byte-parity-tested baseline behind a segmenter seam.
Rajesh approved replacing "byte-identical to the legacy" with a scored comparison, and added two
standing rules: the PRD is not a hard requirement, and every component is designed from the
ecosystem first. Slice C2 built it: 306 tests with the models loaded, the change-point segmenter
placing the one true boundary on the two-topics fixture exactly, the image growing by about 2.3 GB
for torch and the bundled models, and one real bug found in the import order of skops.

He then asked for the same treatment of the editing harness rather than inheriting the legacy's
agent cast. The research, done directly against primary sources, found that the multi-agent
literature of 2025 and 2026 puts the failures in specification, misalignment, and weak
verification, that a single capable model matches agent casts at equal compute, and that the
systems that work in this domain are typed stage decompositions with a critic. The design that
came out is a typed, durable program on Temporal with PydanticAI, five stages, code-then-family
verification, per-seat offline prompt optimisation with DSPy and GEPA, and the C2 metrics as the
promotion gate. Rajesh approved it and corrected one more thing: the design's example seats were
Claude models because the API reference loaded for pricing carries a hard default, against the
repo's own rule of no default vendor. The design now puts every seat behind the gateway, Vercel AI
Gateway leading, with open-weight models such as Kimi K3 first-class in the audition and per-seat
optimisation as the way an open model wins. S3's row, the tech-stack rows, and AGENTS.md were
rewritten on the same PR, and the S3 chassis spec is written for a branch of its own.
