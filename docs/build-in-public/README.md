# Building Temnia in public

**Updated:** 2026-09-08. Rajesh asked for a research-based revision of the earlier posting habits.

The strategy is to make useful work visible: the founder explains decisions and lessons; the product account helps editors and creators understand the chapter-cutting workflow. A daily engineering log supplies evidence, but it does not dictate the public post's structure.

## Start with this experiment

| Account | Initial target | Purpose |
|---|---|---|
| Founder X — @RajeshBuilds | One original post daily | One useful engineering, product or founder insight. |
| Product X — @TemniaHQ | Three original posts weekly | A preview, a workflow lesson and a focused research question. |
| Rajesh's personal LinkedIn | One post each weekday | A substantive lesson for editors, agencies, creators or relevant technical peers. |

That is **10 X posts across both accounts and 5 LinkedIn posts per week**, before optional extras. A second founder X post is welcome when it has an independent takeaway. Start with a **30-minute daily budget** for editing, publishing and useful replies; captures can be batched. These numbers are working choices, not proven platform optima.

Review workload after 14 days and audience response after 28. A difficult build day can use dated backlog; an empty slot can stay empty. Do not sacrifice evidence or building time to hit a count.

Lead with the problem, result or useful observation. `Day N` is optional, usually at the end. Keep the daily series' chronology when using it; do not infer publication from an old draft.

## Today's workflow

1. Record what happened and what was actually verified in [the session log](../log/).
2. Choose the reader and account before writing. Give each original X post a different takeaway.
3. Write clean copy, then check claims, media, length and availability.
4. Rajesh edits and posts. Record the actual account, final copy and publication URL when known.
5. Capture useful questions and revisit them during the weekly review.

The guides contain optional prompts and profile copy. Saving them does not configure accounts, publish posts, schedule work or install a content system. The existing daily logs remain the facts and draft history.
