## Speech performance follow-up: implementation plan (2026-09-09)

The 151-minute qualification succeeded but used 1,021.261 function seconds versus 635.220 for the older combined GPU execution. This is one observation with different CPU limits and no comparable old stage instrumentation. It establishes a regression to investigate, not its cause. Both paths use L4 GPUs. The following work is authorized and is being implemented in this PR; results below remain the previous verified revision until the new gate runs.

1. Remove synchronous progress-network I/O from the inference callback. A dedicated thread with its own asyncio loop publishes a single coalesced latest value at five-second intervals. Permit only one active RPC and one pending value, use a two-second RPC timeout and a five-second shutdown bound, flush best-effort, and retain failures/counts/timings. Callback progress stays monotonic below 100; only a committed stage result signifies completion. A failed progress store cannot fail inference, create unbounded threads, or delay shutdown indefinitely.
2. Make the deployed resource profile explicit and freeze it into run/request identity and reservation calculations. Compare hard-limited four and eight CPU L4/16-GiB profiles with the same model settings, source and weight identity. Validate deployment/profile agreement before booking or dispatch, retain unknown charges, and report measured resource time separately from actual billed cost. Eight CPUs are a candidate, not an assumed winner.
3. Add a versioned topology in which raw speaker turns run alongside recognition followed by alignment. Persist independent raw-turn and aligned-word artifacts, then join them on CPU with both immutable dependency identities. Preserve the serial protocol and its old run/checkpoint interpretation. Still account for every physical GPU call separately; no fourth paid join call. Concurrent reservation remains atomic against one run budget. Success of one branch survives failure of the other, and retries reuse accepted work. On error/cancellation, drain both owned calls; an unconfirmed outcome blocks replacement spending and cleanup. Progress shows stable combined work instead of oscillating stages.
4. Instrument and qualify before choosing a default. Use a small fixture first for output compatibility, callback/network failures and lost-result recovery. Then compare serial baseline/progress fix, CPU limits, and parallel scheduling on the same existing 151-minute two-speaker audio, with explicit build/resource/model identities, repeated paired measurements where they resolve selection, stage/wall times, transcript and speaker differences, and CPU/GPU/progress telemetry. Any model-weight mismatch invalidates a controlled comparison. Container setup/download/checkpoint work is reported separately from inference. Keep single-use containers and create-only execution admission; co-location and GPU snapshots remain later candidates unless evidence warrants them.

Inputs and edges: validate empty/nonfinite progress, bursts/regressions and callback-after-close; reject invalid/mismatched profiles, stage dependencies, source hashes and budgets before dispatch; bound checkpoint payloads and memory independently of source duration. Concurrent/re-entered activities must retain exact operation/attempt identity and immutable checkpoint reuse. Existing known-OOM downgrade remains bounded; unknown provider restarts cannot acquire a second inference admission.

Failure and time: existing one-hour stage and two-minute startup limits remain unless a separately frozen benchmark profile explicitly narrows them. Temporal heartbeat/cancellation must continue while native inference runs remotely. Progress is diagnostic, never liveness authority. The CPU join has bounded inputs and retains both upstream artifacts on failure; no model re-run is necessary to repair the join. Retry and cancel tests prove sibling drainage and accounting retention.

User states: keep current ready/failed/cancelled/unknown/budget semantics and readable recovery actions. Parallel speech needs a truthful stable progress state without falsely completing recognition or speaker work. No new infrastructure controls or benchmark settings enter the editing UI.

Operations and tenancy: use an additive private Modal deployment, dedicated local qualification database and Temporal namespace, and exact owned R2 prefixes. Do not replace shared staging or the existing media application. Pin/reuse the same model files for controlled variants, record their manifest without exposing credentials or transcript content, and clean only owned resources after all calls are terminal. Retain ledger/report evidence before deletion. Benchmark dispatch is sequential by case with an aggregate new exposure ceiling set and recorded before live work, including all unresolved failed attempts; the prior 11,625,003 micros remain separately retained exposure, not available budget.

Verification: focused tests for progress lifecycle, deployment/profile mismatch, atomic parallel admission, two-dependency integrity, cancellation/error races, OOM recovery, checkpoint reuse and lost results; exact transcript/speaker fixture parity; isolated live short and long runs; then the complete exact-commit local release gate, both images, production browser suite and `pnpm push:verified`. Record the selected configuration, rejected alternatives, actual measurements, limits, cleanup, durable decision and daily log in the same change. No latency, quality or billing win is claimed before evidence. No merge is included.

### Controlled experiment limits

The reviewed benchmark profile narrows the GPU deadline to 900 seconds plus 120 seconds startup (the longest previously observed stage was 479.815 seconds). Production remains 3,600 plus 120. Four variants run one 40-second preflight and two long repetitions each: synchronous/4-core/serial, coalesced/4-core/serial, coalesced/8-core/serial, coalesced/8-core/parallel. Blocks use reversed order. No OOM fallback or extra repetition is admitted inside this experiment. The fixed rates are 1,250,000 and 1,450,000 micros/hour, above the September 9 published resource floors of 1,115,712 and 1,304,352. Thirty-six calls reserve at most 13,770,018 micros under a non-recyclable 14,000,000-micro ($14) new experiment ceiling. Existing 11,625,003 micros of unresolved prior exposure remain separate and retained. Model preparation CPU usage is separately capped and reported. Resource estimates are not invoices. Any unknown execution, identity mismatch, malformed output, OOM or deadline stops subsequent long dispatches until investigated; no cap is silently raised.
