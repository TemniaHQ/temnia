# Standalone-topic model evaluation

September 11, 2026. Rajesh requested model evaluation after PR #36 and merged it as
`a96b571490aa6954d158b5cdda60055f1e4e9e81`. This is the fixed starting implementation.
The objective is better worthwhile-discussion recall and fewer weak selections,
with completion and fidelity preserved. Qualification is not editorial acceptance.

## Experiment and implementation boundary

1. Freeze the actual running control snapshot, effective settings and source evidence.
   Keep historical v1 runs separate from v2 model swaps; changing the programme and a
   model simultaneously does not isolate a model effect. Preserve all old expenses.
2. Refresh public gateway model and provider metadata. Qualify exact v2 native requests
   for the existing control routes and capable alternatives across GPT, Claude, Gemini,
   Kimi, DeepSeek and GLM where policy and actual transport allow. Model names in the
   supplied plan are candidates, not winners. Keep mandatory ZDR, provider pinning,
   no silent fallback and independently reserved reviewer family. Do not admit a route
   from old-schema proofs. Fable remains excluded by the existing repository decision.
3. Use the current qualifier and its journals/receipts on synthetic source evidence.
   Freeze explicit output/reasoning settings and conservative price observations.
   Derive execution exposure from the exact planned requests; introduce no arbitrary
   model, source-duration, output-count or experimentation-spend ceiling. Unknown
   outcomes stop their journal and are reconciled without replaying inference.
4. Prepare controlled full-workflow cases using the existing TopicSelectionWorkflow,
   run creation, scoped database, source storage and paid-operation runtime. An isolated
   worker/configuration must bind to each declared route snapshot so changing the
   experiment does not silently change general staging. Keep full source sentences,
   transcript revision, rubric and detector fixed. PySceneDetect AdaptiveDetector is
   the requested trial; an FFmpeg comparison is a separately declared factor.
5. Initial author outputs can be screened separately from their later repairs. Hold
   reviewers fixed in model-swap comparisons; author and repair currently share a seat,
   so report that fact rather than call repaired results a pure author-only effect.
   Reviewer calibration uses identical independently labeled good and defective cases,
   cold/source contexts separated. Do not use uncalibrated model verdicts as human gold.
6. Existing recordings are development material. Reserve complete fresh recordings for
   confirmation and identify prior exposure. Prepare blind candidate review materials
   and whole-source opportunity labels without inventing annotator identities or
   measurements. Text judgments and actual playback acceptance remain different scopes.
7. Compare baselines and finalists through rendering and human judgment, retaining
   refusals, failures, abstentions, unknowns, edits, costs and source-level denominators.
   No winner or rollout is established by schema success or a single impressive result.

### Initial evaluation projection work

Read-only preflight found two projection errors that prevent a valid actual model-swap
comparison: source bytes SHA is retained on evidence artifact metadata but the exporter
looks only for an absent run-pinned SHA; execution identity includes the route snapshot
ID, so an intended route swap also appears to change a supposedly fixed factor.

Correct source identity using the verified source-evidence artifact metadata, with
conflicting available identities refused and genuinely absent identities kept unknown.
Separate route identity from non-route execution settings; retain the complete route
snapshot independently. Comparison must still detect unintended reviewer, reasoning,
prompt, source, rubric, detector and execution-setting changes. Add focused regression
cases using production-shaped run configuration and artifact metadata rather than only
hand-assembled comparison records. Do not weaken general source/identity validation.

Conditional repair also changes the set of observed response prompt/schema IDs even
when the intended programme is identical. Freeze the complete intended roster before
dispatch in the run wrapper's `evaluationProgram` plus its canonical
`evaluationProgramSha256`. The strict `TopicProgramManifest` records policy,
implementation build SHA-256, programme version and every intended stage's seat,
prompt version/template SHA-256 and native schema version/SHA-256. V2 requires author,
cold, source and patch stages. Template hashes cover input-independent prompt function
source; they are not hashes of one episode's rendered prompt. The optional run-creation
binding preserves this metadata immutably; refetching without a new manifest keeps it.

Project these intended identities into controlled comparison factors and retain
observed attempt stage/version/hash/route identities separately. Refuse observed IDs
or available template/schema hashes that conflict with the declared roster. Historical
runs without that frozen metadata keep unknown intended programme/prompt/schema
identities and are explicitly incomparable; current runtime constants must not fill
their missing history. Preserve complete original run configuration, including its
route snapshot ID, outside the non-route execution comparison factor.

If actual dispatch requires an additional runner, specify its complete request/ownership
and replay contract before implementing it. Prefer reusing existing production run
creation and workflow controls over a second orchestration or paid-accounting path.
A report command is never a hidden dispatch command. No UI, tenancy, billing or unrelated
runtime rewrite is included.

## Inputs, operations and failure behavior

- Empty/oversized sources, duplicate case IDs, stale evidence, missing qualification,
  source/rubric mismatch and unintended changed factors refuse explicitly before dispatch.
- Keep credentials inside existing server/process environments and raw source artifacts
  private. Public records contain identities, exact costs and results, not source speech,
  credentials or provider reasoning.
- Isolated execution binds the merged or later verified code identity, dependency versions,
  exact prompts/native schemas, actual model/provider/settings and complete source hashes.
  An image without the required programme is an unavailable experiment runtime.
- Existing reservations and unknown-outcome fences apply. Do not reset an unknown run or
  create another journal to evade it. Cancellation preserves known paid work and receipts.
- Source download, evidence production, compilation/rendering and human review retain
  their existing progress, leases and finite revision semantics. A source-context or
  physical-cut failure is not automatically a model quality failure.
- Keep the current staging feature flag off until deliberate experiment configuration;
  merge alone is not rollout. Preserve prior configuration for any authorized isolated
  run, and inspect boot health/configuration before inference.
- Human opportunity labels must be independent of model portfolios. A source-aware
  reviewer cannot also be claimed as an unexposed cold viewer. Missing labels remain
  pending while transport and development work proceeds.

## Controlled workflow launcher contract

The read-only execution inspection confirmed that there is no operator audition launcher,
although the complete production v2 workflow already exists. Add a small Python-only
operator manifest and `prepare`, `run` and read-only `status` commands around that workflow.
It is an experiment interface, not another editing programme or durable runtime.

Preparation freezes source ID, source fingerprint/known bytes hash, ready transcript
identity/revision/hash, source group/split, brief/rubric, exact run settings, route snapshot
and its resolved author/reviewer, code/prompt/schema identities, qualification evidence,
arm-specific pipeline/control queues, and stable run/request/workflow UUIDs. Files are
create-only/private. Reject empty/duplicate arms, output overwrite, invalid snapshot,
missing qualification and incompatible requested settings before any paid operation.
Keep expected and subsequently observed evidence separate when evidence has not yet
been built; missing source SHA cannot become a guessed value.

Execution reuses scoped `start_or_refetch_run` and `TopicSelectionWorkflow`, existing
source pinning, reservation/response/expense paths and PydanticAI registrations. A worker
runs unchanged on each isolated queue using the manifest's exact configuration. Verify
resolved model seats and worker/runtime settings; do not mutate the general staging
worker configuration or let differently configured workers share the experiment queue.
Precreate/refetch the durable source-pinned run and compare its actual pinned source and
transcript against the manifest before starting its workflow. This removes any need to
change the production request schema to admit external candidate artifacts. Any source
bytes/evidence mismatch discovered later makes the result incomparable and is retained
as an operational outcome; it cannot be silently accepted as a controlled source.

Workflow start uses the prepared immutable ID and intent. After an uncertain start,
inspect/reuse exactly that identity; never generate a replacement paid run. Status is
read-only and never dispatches. Retain failed/prepared-but-unstarted states clearly.
The initial proposal is identified from retained model-origin selection records without
parents; repaired final outcomes remain separate. Author and repair share the current
production author seat, and cold/source share the verifier seat; configuration names
and reports must state this coupling.

Freeze the intended prompt/schema roster separately from the set of calls observed.
A conditional repair is an outcome under the same programme, not a changed fixed prompt.
Historical missing programme facts remain unknown; current constants alone cannot
retroactively establish the identity of an older run. New experiment manifests provide
an exact versioned roster that can be checked against retained call metadata.

Add meaningful tests for stable intent/reentry and uncertain workflow starts, incompatible
source/configuration/queue refusal before start, qualified frozen routing and source pinning,
read-only status, and export-derived comparisons with conditional repair. Fixed-candidate
reviewer auditions remain a separately specified next execution step; transport qualification
is not silently repurposed as reviewer calibration.

The operator commands ship in the pipeline image alongside the build declarations used
by the existing source-input fingerprint. Preparation and execution can then use the
same verified image as the isolated worker. This adds only the launcher script and the
two Dockerfiles as inert files; it changes no worker entry point or shared runtime
configuration. Verify checkout/image fingerprint parity during the image gate and
record the actual image identity separately: an input hash alone does not attest a
running worker or immutable upstream dependencies.
